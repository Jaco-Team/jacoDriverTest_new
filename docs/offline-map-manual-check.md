### Обновление: что именно подтверждено

На сайте проверено реальное выполнение обновления с паузой и продолжением при
сохранении старой карты. В приложении SDK управляет версиями пакетов: совпадение
установленного и доступного релиза может завершить команду без повторной загрузки.
На Android это подтверждено журналом 16:19: Тольятти, регион 240,
оба релиза `1795062627000`, `completed`, `downloadStarted=false`.
Это не проверка установки более нового пакета и не доказательство свежего
сетевого запроса каталога. На iPhone подтверждено наличие кнопки «Обновить»;
отдельный ручной прогон её действия не зафиксирован.

## Подготовка

Проверять отдельно: сайт на компьютере; сайт на Android и iPhone, если им
пользуются курьеры; приложение Android; приложение iPhone. Загрузки привязаны
к конкретному браузеру/установке приложения и не переносятся между ними.
Использовать один и тот же город и рабочее кафе. Выбор другого города в
«Офлайн-картах» не переключает рабочее кафе.

Сначала проверить ранее скачанную карту после установки обновления поверх
прежнего приложения. Не удалять приложение и его данные: иначе проверка
миграции старых записей потеряет смысл. Новая отдельная тестовая установка
Android имеет собственные карты, её нужно проверить дополнительно.

### Сайт с локальным API

Обычный `npm run dev` намеренно отключает service worker и не подходит для
проверки перезапуска сайта без сети. Остановить dev-сервер сайта через Ctrl+C,
оставив локальный API на порту 8080, затем выполнить самостоятельно:

```bash
cd /Users/denis/Public/work/jaco_driver_site
export PATH="/Users/denis/.local/share/fnm/node-versions/v24.15.0/installation/bin:$PATH"
NEXT_PUBLIC_API_ORIGIN=http://localhost:8080 \
NEXT_PUBLIC_MEDIA_ORIGIN=http://localhost:8080 \
NEXT_PUBLIC_API_PROXY=true \
npm run preview:offline
```

Эта существующая команда делает локальную рабочую сборку в `.next-preview`
и запускает её на `http://localhost:3225`; публикации нет. Открыть сайт с сетью,
войти, открыть настройки. Дождаться готовности карты. При первой регистрации
service worker может потребоваться обновить страницу с интернетом.
В DevTools → Application → Service Workers не включать «Bypass for network».
Использовать обычную вкладку, не приватный режим.

На реальном телефоне service worker требует HTTPS: использовать уже доступный
тестовый HTTPS-адрес с этими изменениями. Адрес Mac вида `http://192.168.…`
не подходит для полной проверки браузерного офлайн-запуска. Новую публикацию
или сетевой туннель этот документ не запускает.

### Приложение

Нужна полная пересборка Android и iOS: изменён нативный мост MapKit и его
сохранённый patch-package. Обновления JavaScript/Metro недостаточно. Новых
пакетов нет; обновлять зависимости через `npm update` не требуется.

Из корня `jacoDriverTest_new` для iOS сначала выполнить `npm run ios:pods`,
чтобы обновить сгенерированный интерфейс нативного модуля, затем пересобрать.
Текущий Debug получает JS из Metro. Холодный старт без Metro проверять в Release.

Для отдельного Android-приложения с локальным API:

```bash
cd /Users/denis/Public/work/jacoDriverTest_new
export PATH="/Users/denis/.local/share/fnm/node-versions/v24.15.0/installation/bin:$PATH"
JACO_LARAVEL_API=local SENTRY_DISABLE_AUTO_UPLOAD=true \
SENTRY_DISABLE_NATIVE_DEBUG_UPLOAD=true npm run android:build:local
```

APK: `android/app/build/outputs/apk/localRelease/app-localRelease.apk`.
Его можно установить из Android Studio либо самостоятельно через `adb install -r`.
Это отдельное приложение «Курьер Жако (тест)» с отдельными данными.
Для подключения к локальному API через USB/Android-эмулятор нужен
`adb reverse tcp:8080 tcp:8080` для выбранного устройства: конфигурация local
использует `http://localhost:8080`. При нескольких устройствах выбирать serial.

Для созданного iPhone 17 Simulator с локальным API:

```bash
JACO_LARAVEL_API=local SENTRY_DISABLE_AUTO_UPLOAD=true \
SENTRY_DISABLE_NATIVE_DEBUG_UPLOAD=true npm run ios -- --simulator "iPhone 17" --mode Release
```

На физическом iPhone `localhost` относится к телефону. Для него использовать
доступный с телефона тестовый API и принятую в проекте конфигурацию; самовольно
менять адрес в коде для этой проверки не нужно. Пересобрать через Xcode в Release.
Сохранять установленную рабочую версию и её карты при проверке обновления.

## Дополнительные проверки сайта на локальном preview

Эти действия выполнять только в тестовом браузере на тестовом адресе.
Не менять часы телефона/компьютера ради имитации срока карты.

### Истечение срока без ожидания 29 дней

Сначала скачать Тольятти. В консоли тестовой вкладки изменить только срок записи:

```javascript
const key = 'jaco_yandex_offline_maps_v2';
const registry = JSON.parse(localStorage.getItem(key));
registry.regions['city:tolyatti'].expiresAt = Date.now() - 1000;
localStorage.setItem(key, JSON.stringify(registry));
location.reload();
```

Галочки нет, указано истечение срока. Офлайн-карта не выдаётся за пригодную.
После восстановления сети нажать кнопку скачивания/обновления и дождаться готовности.
Искусственно изменённая дата не моделирует возраст каждого тайла, поэтому
тесты отдельно проверяют политику хранения.

### Потеря части тайлов

Для простоты оставить скачанным только один тестовый город. В DevTools →
Application → Cache Storage → `jaco-yandex-offline-tiles-v1` удалить один тайл.
Перезагрузить страницу. Должна исчезнуть галочка и появиться сообщение о неполной
карте. Остальные тайлы сохраняются. «Продолжить» докачивает недостающее.

### Потеря файлов открытия сайта

С сетью, в том же тестовом браузере удалить из `jaco-offline-app-v2` один JS-файл,
на который ссылается сохранённая страница `/map_orders`. Открыть настройки заново.
Карта не должна показывать полную офлайн-готовность. Повторная подготовка через
кнопку обновления должна восстановить файл. Затем повторить холодный офлайн-запуск.

## Статусы SDK, которые нельзя надёжно получить вручную по команде

`outdated`, `need_update`, `unsupported`, смена установленной версии и ошибка
SDK при запуске зависят от SDK и состояния пакета. Если такие состояния реально
есть — проверить соответствующее поведение. Подмена одной записи AsyncStorage
не подтверждает пригодность нативных файлов. Эти переходы покрыты добавленными
сценариями тестов с ответами SDK; сами тесты ещё не запускались.

## Обновление приложения: исправление преждевременного завершения — 19 ноября 2026

Кнопка «Обновить» возвращена для скачанной пригодной карты на Android и iOS.
Нажатие явно вызывает startDownload и для completed. Служебные сообщения

удаление старого пакета или принудительная очистка данных.

Подтверждённый дефект кода: startOfflineRegionDownload разрешал Promise сразу
после команды startDownload. JS затем считывал completed/progress=1 старого
пакета и принимал это за завершение попытки, освобождал слот и снимал намерение
автопродолжения. Установленный релиз не сравнивался с релизом каталога, а события
RegionListener не учитывались. По одному мельканию интерфейса нельзя различить
это преждевременное завершение, отсутствие нового релиза и ошибку SDK.

Теперь мост передаёт availableReleaseTime из Region.releaseTime и факт перехода
в downloading после текущей явной команды. RegionListener сохраняет этот факт,
даже если JS не успел опросить короткую загрузку. Общая ошибка OfflineCacheManager
передаётся активной загрузке так же, как ошибка региона, вместо сохранения только
в диагностике каталога. Новая попытка сбрасывает сведения предыдущей попытки.
Нативные изменения сохранены также в patch-package.

Старый completed больше не завершает ожидающую попытку при новом или неизвестном
релизе каталога. Ожидание заканчивается фактическим переходом SDK, установкой
другого релиза, ошибкой либо completed с совпадающим/более новым установленным
релизом относительно каталога. Последний случай означает, что пакет уже
соответствует данным каталога SDK; это не доказательство свежего сетевого запроса
или повторного скачивания. Дата сохранения не меняется для прежнего релиза.

отменить подготовку. Старая пригодная карта и её галочка остаются доступными.

### Диагностика после отката: только системный журнал

После отката функциональные условия MapScreen и offlineMap.store оставлены
как в проверенном Android-варианте. Добавлено наблюдение за уже совершённым
рендером: ui_state содержит hydrated, homeReady, наличие контекста заказов,

(offline-list/map/loading). Эти значения не участвуют в выборе состояния.
Нет таймеров, записи в бизнес-хранилища, сетевых запросов и новых UI-текстов.

Для Release используется отдельный void-метод нативного журнала
logOfflineMapState(string); он доступен на обеих платформах, не обращается к
MapKit и не меняет его состояние. В iOS дополнительно записываются уже
возвращаемые каталог/статус и события SDK. Установленные релизы и данные
готовности не меняются. Логирование не содержит токенов, координат, адресов
и данных заказов; одинаковые SDK-снимки не повторяются.
Изменения библиотеки сохранены в patch-package. Для новой декларации журнала
требуется обновить iOS codegen через ios:pods и пересобрать Release. Зависимости
не добавлялись; скачанные карты удалять не нужно.

Журнал на Mac следует начать ДО воспроизведения: оставить один нужный iPhone
Simulator запущенным, начать команду, затем закрыть приложение, отключить сеть
на Mac, открыть приложение и «Карту заказов». Когда появится карта, остановить
Ctrl+C, вернуть сеть и передать вывод. Сам агент этого не запускает:

```bash
xcrun simctl spawn booted log stream --style compact --level debug --predicate 'eventMessage CONTAINS "JacoOfflineMap"'
```

Причину определять по ui_state с surface=offline-list и соседним status_returned:
нет homeReady/cityId — ещё не восстановлен контекст; нет entryPresent — нет
записи города; checking — ожидание SDK; missing/invalid — проверить, что SDK
фактически возвратил перед этим. Это перечень различимых гипотез, а не диагноз
конкретного запуска. Дальнейшая функциональная правка до полученного журнала
не делалась. Тесты, сборки и устройства агентом не запускались.


### 19.11.2026: причина списка при старте подтверждена журналом iPhone

При нескольких booted-симуляторах alias `booted` выбрал iPad Pro 11-inch
(42479CB4-5104-4CE6-A215-CA6AECF5BE7E) с com.jaco.cookapp. Поэтому прежний
пустой журнал не доказывал отсутствие сообщений в Курьере. С явным UUID
iPhone 17 (62B06A16-216E-4145-BB91-79DF796B6178) приложение и оба журнала работают:

```bash
xcrun simctl launch --terminate-running-process --console-pty 62B06A16-216E-4145-BB91-79DF796B6178 org.reactjs.native.example.jacoDriverTest
```

В воспроизведении 18:14:37 каталог SDK пуст, catalogUpdated=false,
Тольятти (240) возвращает unsupported без сведений об установленном релизе.
В 18:14:40.287 UI: offline=true, hydrated=true, homeReady=true,
availability=invalid, status=error, surface=offline-list. В 18:14:42.843
после загрузки местного каталога тот же SDK возвращает completed с релизом
1795062627000; в 18:14:42.856 UI выбирает map. Список виден около 2,6 с.
Пользователь подтвердил видимый список именно в этом запуске. Два предыдущих
старта без списка открывали карту уже после подтверждения пакета.
Таким образом, для пойманного iOS-запуска исключены отсутствие координат кафе,
отсутствие записи города и утрата скачанного пакета. Android с таким симптомом
пользователь наблюдал, но аналогичная последовательность его журнала не снята.

В исходники внесена обработка достоверности нативного статуса:

- В Android/iOS getOfflineRegionStatus дополнен stateKnown. Он false только
  для unsupported при пустом каталоге до первого onListUpdated. Непустой
  каталог учитывается и при подписке после события. JSON расширен без новых
  нативных методов, зависимостей или изменения codegen-деклараций.
- readStatus при stateKnown=false оставляет availability=checking и сохраняет
  статус загрузки, прогресс, дату, установленный релиз, ошибки и autoResume.
  Подтверждённые unsupported/need_update/available обрабатываются как прежде.
- Пока offline-запись проверяется или ещё восстанавливается из хранилища,
  MapScreen показывает существующий индикатор загрузки вместо преждевременного
  fallback-списка. После проверки выбирает MapKit или список по реальному
  результату. Онлайн-условия не менялись; новых UI-текстов и таймеров нет.
- resumePending сохраняет намерение автоматического продолжения, но не
  отправляет команду, пока availability=checking. Ручная пауза остаётся ручной.
  Реализации download/pause/remove/setRuntime побайтово совпадают с копией
  перед этой правкой. Логика обновления, релизов и ошибок не переписывалась.

Изменения нативных файлов сохранены в существующий patch-package с сохранением
остальных правок. Структура затронутых нативных hunks сверена с текущими файлами.
Добавлены регрессии холодного восстановления, предварительного/подтверждённого
unsupported, сохранения ручной/автоматической паузы и переходов UI checking ->
ready/missing/invalid. Они НЕ запускались. Git, приложения, устройства,
эмуляторы, линтеры, сборки и тестовые раннеры агентом не запускались.

Исправление пока проверено чтением исходников; успешное поведение новой сборки
не подтверждено. Нужна пересборка нативной части для каждой платформы. Сначала
повторить на iPhone пойманный ранний вход в карту до окончания проверки SDK:
ожидается loading -> map без offline-list. Затем проверить окончательно
отсутствующую карту и прежние сценарии паузы/возобновления/удаления на обеих
платформах. Скачанные карты и данные приложения очищать не требуется.
