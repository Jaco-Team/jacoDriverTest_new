# Синхронизация темы сайта и мобильного приложения

Дата решения: 22 сентября 2026 года.

Статус на 01.10.2026: сайт и приложение уже читают и отправляют `app_theme`,
а приложение кэширует выбранный режим локально. Этот документ сохраняет
принятый контракт и порядок внедрения; production-миграцию БД и сквозную
синхронизацию одного аккаунта между тремя клиентами по нему нельзя считать
проверенными без отдельного теста на рабочем backend.

## Итоговое решение

На курьерском сайте и в мобильном приложении используется одна настройка темы
интерфейса:

```text
app_theme: system | light | dark
```

Пользователь видит одинаковый выбор:

- `Системная`;
- `Светлая`;
- `Тёмная`.

Выбранная тема применяется ко всему интерфейсу, включая карту. Отдельной
пользовательской настройки темы карты нет.

Поле `theme` по-прежнему отвечает только за оформление текста и маркеров карты и
не участвует в выборе светлой или тёмной темы приложения.

## Поведение режимов

- `system` — сайт использует `prefers-color-scheme`, мобильное приложение — тему
  Android или iOS; фактический вид одного аккаунта может различаться на
  устройствах с разными системными темами;
- `light` — сайт, приложение и карта всегда светлые;
- `dark` — сайт, приложение и карта всегда тёмные;
- при отсутствии серверной настройки используется `system`;
- серверное значение имеет приоритет, локальное хранение используется только как
  кэш для быстрого и офлайн-запуска.

## Почему тема карты не настраивается отдельно

Отдельный boolean создаёт неоднозначность: при тёмной системной теме, выбранной
тёмной теме приложения и выключенном переключателе карты невозможно сразу понять,
какой режим должен победить. Реальной подтверждённой потребности использовать
светлый интерфейс с тёмной картой или наоборот сейчас нет.

Если такая потребность появится после обратной связи курьеров, настройка карты
должна добавляться отдельным явным режимом `Как в приложении | Светлая | Тёмная`,
а не неоднозначным чекбоксом.

## Изменения Laravel API и БД

Контракт предусматривает поле `app_theme` со строковым значением,
а не использование `dark_theme = 0/1/2`: старое название и текущая Laravel-
валидация подразумевают boolean, а старые клиенты могут неправильно обработать
значение `2`.

На переходный период:

- `dark_theme` и `night_map` остаются в контракте для старых клиентов;
- новые версии сайта и приложения читают `app_theme`;
- сохранение `light` и `dark` при необходимости временно дублируется в
  `dark_theme` для обратной совместимости;
- новые клиенты не используют `night_map` как источник темы карты;
- после обновления сайта и приложения старые поля помечаются устаревшими и
  удаляются отдельным этапом, только после проверки production-использования.

## Миграция данных

Безопасный вариант, сохраняющий текущий вид существующих пользователей:

- `dark_theme = 1` → `app_theme = dark`;
- `dark_theme = 0` → `app_theme = light`;
- `dark_theme IS NULL` → `app_theme = system`;
- новые аккаунты → `app_theme = system`.

Перед миграцией необходимо проверить фактическую production-схему и количество
значений `NULL`, `0` и `1`.

## Порядок выпуска и оставшиеся проверки

1. Добавить поле, миграцию, API-контракт и тесты в `laravel-api-driver`.
2. Обновить `jaco_driver_site`: три режима, `prefers-color-scheme`, серверное
   сохранение, карта следует фактической теме.
3. Обновить `jacoDriverTest_new`: серверное значение вместо локального источника,
   локальный кэш и карта по фактической теме.
4. Проверить старые и новые клиенты в переходный период.
5. После общего релиза отдельно решить удаление legacy-полей.

## Критерии готовности

- новый аккаунт получает `system`;
- `system` реагирует на изменение темы устройства или браузера;
- `light` и `dark` не меняются вместе с системной темой;
- один аккаунт получает одинаковый выбранный режим на сайте, Android и iOS;
- при `system` фактический вид может различаться вслед за темой устройства;
- карта всегда соответствует фактической теме интерфейса;
- без сети используется последнее сохранённое значение;
- после восстановления сети серверное значение снова становится источником;
- API принимает только `system`, `light` и `dark`;
- миграция и серверный round-trip покрыты тестами.
