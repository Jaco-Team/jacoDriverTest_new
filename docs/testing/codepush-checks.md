# CodePush для приложения курьеров

Один документ об устройстве, подготовке обновлений и результатах проверок Android и iOS.

## Что обновляется

CodePush доставляет JavaScript-код для установленной нативной сборки. Для каждой платформы собирается отдельный бандл: `index.android.bundle` для Android и `main.jsbundle` для iOS. ZIP и загрузка новых локальных ресурсов не используются.

Код загружается из существующего бакета `jaco-driver-codepush` в Yandex Object Storage:

```text
https://storage.yandexcloud.net/jaco-driver-codepush/
  android/<runtimeId>/manifest.json
  android/<runtimeId>/releases/<sha256>.bundle
  ios/<runtimeId>/manifest.json
  ios/<runtimeId>/releases/<sha256>.jsbundle
```

Папки с `runtimeId` разделяют обновления, подходящие для конкретной нативной сборки. В приложение встроен собственный JS-бандл, который остаётся доступным при отсутствии подходящего обновления.

## Запуск, установка и откат

1. При обычном холодном открытии Release нативный код проверяет S3 до запуска React Native. На заставке он ждёт сетевую проверку до 8 секунд и локальный выбор до 2 секунд.
2. Если подходящий пакет готов вовремя, приложение пробует его запустить. Если проверка не успела, запускается прежняя версия; поздно скачанный пакет может примениться при следующем обычном открытии.
3. Запущенное приложение само не перезагружается. Возврат из фона, push и ссылки не начинают новую пробную попытку. В Debug используется Metro; такой запуск не проверяет CodePush.
4. Новая версия подтверждается после восстановления локальных данных, подготовки встроенных ресурсов, отображения нужного экрана и перехода приложения на передний план. Успех сетевого запроса и наличие заказов для подтверждения не требуются.
5. Если пробный запуск не подтвердился, при следующем запуске выбирается доступная рабочая или встроенная версия. Неисправный бандл помещается в карантин по хешу и повторно не запускается.

Уже подтверждённая версия может запускаться без сети; для нового применения сохранённого кандидата остаются обязательными действующие условия допуска.

Подтверждение относится к конкретной попытке и процессу. Закрытие приложения до подтверждения тоже считается неподтверждённым запуском; само по себе это не доказывает crash. При обнаруженной фатальной ошибке JS после подтверждения механизм записывает сбой и при следующем открытии выбирает предыдущую рабочую или встроенную версию. Для записи отводится до двух секунд, после чего ошибка передаётся прежнему обработчику. Если ошибка нативная или запись сбоя не удалась, автоматический откат не гарантируется.

Обновление и откат не должны удалять авторизацию и данные курьера. Нативный откат JS не отменяет изменения, уже отправленные на сервер; миграции локальных данных должны оставаться совместимыми с рабочей резервной версией.

## Совместимость и проверка пакета

Каждая APK/IPA содержит `nativeRuntimeId`, который учитывает платформу, идентификатор и номер сборки, React Native/Hermes, нативные зависимости и настройки, встроенные ресурсы, контракт хранения и доверенные ключи. Пакет готовится по метаданным именно той нативной сборки, для которой предназначен. При несовместимости он не применяется.

Оболочка манифеста содержит `keyId`, `payloadBase64` и `signatureBase64`. Подписываются контекст `jaco-driver-codepush-manifest-v1\n` и точные байты содержимого; алгоритм — ECDSA P-256 с SHA-256. Приложение проверяет подпись встроенным публичным ключом, затем проверяет схему, совместимость, срок, адрес, размер и SHA-256 бандла. Недокачанный или повреждённый файл не становится кандидатом.

Манифест содержит `manifestSequence`, идентификатор и версию релиза, время начала и окончания действия, `enabled`, долю распространения и данные пакета. Номер публикации должен возрастать для соответствующих платформы и runtime. Для возврата прежнего файла в S3 нужен **новый подписанный манифест с большим номером**; повтор того же номера допустим только для тех же подписанных данных. Локальное восстановление сохранённой рабочей версии не зависит от этого правила.

Скачивание выполняется по HTTPS без перенаправлений. Проверяются подписанный размер и хеш; при наличии проверяется и `Content-Length`. Предел бандла — 128 МиБ, резерв свободного места — 16 МиБ. Прерывание, нехватка места или недоступная сеть не должны заменять рабочую версию неполным пакетом. Сетевой бюджет загрузки — до 120 секунд; это не означает, что приложение ждёт загрузку на заставке всё это время.

`enabled=false` запрещает новые применения после получения манифеста. Уже подтверждённая версия продолжает работать; устройство без сети не узнаёт об остановке мгновенно. Возврат прежнего манифеста также не означает мгновенное переключение уже работающего JS.

## Изображения и шрифты

После обновления используются изображения и шрифты, уже встроенные в установленную APK/IPA. Добавление или замена локальных файлов, в том числе ранее не упакованных ресурсов, требует новой нативной сборки. Изображения по URL загружаются по обычным правилам приложения; их наличие без сети зависит от кэша и не гарантируется CodePush.

## Ключи и доступ к S3

Ключ подписи CodePush и ключ доступа к S3 решают разные задачи. Приватный ключ подписи хранится вне репозитория и приложения; публичный набор встраивается в APK/IPA. При смене доверенных ключей нужна новая нативная сборка. Секреты S3 и приватный ключ нельзя включать в Git или бандл.

В этой рабочей среде файлы ключей находятся в `/Users/denis/.config/jaco-driver-codepush/keys/`:

- `private.pem` — приватный ключ подписи;
- `public.pem` — публичный ключ;
- `trusted-keys.json` — набор публичных ключей для нативной сборки.

Локальный `.env` содержит идентификатор ключа и пути к файлам, а не содержимое ключей. Шаблон переменных — в [`.env.example`](../../.env.example): `CODEPUSH_KEY_ID`, `CODEPUSH_PRIVATE_KEY_FILE`, `CODEPUSH_PUBLIC_KEY_FILE`, `CODEPUSH_TRUSTED_KEYS`. Значения из окружения имеют приоритет; пути нужны абсолютные. Если доверенные ключи не настроены при нативной сборке, она не сможет принять подписанное обновление.

Для загрузки в S3 используется AWS CLI с профилем `mini-codepush`, регион `ru-central1` и endpoint `https://storage.yandexcloud.net`. Приложению для чтения обновлений ключи записи в S3 не передаются.

## Подготовка и публикация обновления

Нужны обычные APK/IPA или iOS `.app`, в которые уже встроен CodePush и доверенный публичный ключ. Для проверки используется Release без Metro. Если изменились нативные зависимости, настройки сборки, встроенные ресурсы или ключи, сначала нужна новая нативная сборка и новый экспорт её runtime.

1. Экспортировать метаданные из конкретных нативных артефактов. Пути в примерах нужно заменить на свои; родительские каталоги должны существовать, выходных файлов ещё не должно быть:

   ```bash
   npm run codepush:runtime -- export /path/to/app.apk /path/to/android-runtime.json
   npm run codepush:runtime -- export /path/to/app.ipa /path/to/ios-runtime.json
   ```

   Вместо `.ipa` допускается `.app`. Экспорт не устанавливает приложение и не публикует обновление.

2. Подготовить `release.json` с полями `manifestSequence`, `releaseId`, `version`, `issuedAt`, `expiresAt`, `enabled`, `rolloutBasisPoints`, `rolloutSeed`. Указать новый возрастающий sequence, корректный срок действия в UTC и одинаковые параметры релиза для обеих платформ. `rolloutBasisPoints` задаёт долю от 0 до 10000; значение 10000 включает все установки.

3. Создать общий каталог и собрать подписанные бандлы в двух новых подкаталогах:

   ```bash
   mkdir -p /path/to/pair
   npm run codepush:build -- --platform android --runtime /path/to/android-runtime.json --release /path/to/release.json --out /path/to/pair/android
   npm run codepush:build -- --platform ios --runtime /path/to/ios-runtime.json --release /path/to/release.json --out /path/to/pair/ios
   ```

   Существующие каталоги результата не перезаписываются. Сборка локальная: она не загружает файлы в S3. Приватный ключ берётся из настроек; его публичная часть должна совпадать с ключом внутри выбранной сборки.

4. Проверить подготовленные пакеты без публикации:

   ```bash
   npm run codepush:publish:all -- --prepared /path/to/pair
   ```

5. После проверки опубликовать обе платформы одной командой:

   ```bash
   npm run codepush:publish:all -- --prepared /path/to/pair --execute
   ```

Публикация проверяет пакеты, размещает неизменяемый бандл, проверяет его публичное чтение и только затем обновляет манифест. Платформы публикуются последовательно, общей транзакции нет: при ошибке нужно посмотреть, какая платформа завершилась, и повторно проверить состояние. `metadata` и `debug` из локального результата не предназначены для публикации; source map находится в `debug`.

Первый выпуск CodePush и публикацию для курьеров выполняет руководитель после проверки. Документ не заменяет проверку применимых требований магазинов: [Apple App Review](https://developer.apple.com/app-store/review/guidelines/#software-requirements), [условия Apple Developer Program](https://developer.apple.com/support/terms/apple-developer-program-license-agreement/), [правила Google Play](https://support.google.com/googleplay/android-developer/answer/16559646?hl=en).

## Диагностика

Экран диагностики открывается удержанием логотипа на экране входа или основного заголовка около 3 секунд. Он показывает источник запуска, выполняемую и подтверждённую версии, кандидата, результат загрузки, последнее событие и подробные идентификаторы пакетов. Кнопка «Обновить сведения» только перечитывает локальное состояние — она не запускает загрузку или установку.

«Кандидат» означает сохранённый пакет, а не обязательно выполняемый код. `launch_unconfirmed` означает неподтверждённый запуск; причину завершения нужно устанавливать отдельно. `lock_busy` может появиться во время работы загрузчика — повторное чтение имеет смысл после окончания операции.

Экран показывает тип сборки «Release» или «Debug» по данным нативной диагностики. Если данные недоступны, отображается «Нет сведений».
