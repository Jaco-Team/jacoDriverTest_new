# Release checklist

## Цель документа

Этот чеклист нужен для повторяемой проверки перед релизом `jacoDriverTest`.

Автоматический baseline уже добавлен. Чеклист разделен на:

- локальную проверку;
- GitHub-проверку;
- ручные сценарии.

## Локальный automatic baseline

Перед релизом должны проходить:

```bash
npm run lint
npm run typecheck
npm run test:unit
```

Подробности:

- [docs/quality-baseline.md](../quality-baseline.md)

## GitHub baseline перед merge

После внедрения GitHub Actions перед merge также должен быть зеленым check:

- `CI Baseline / lint-typecheck-unit`

Он должен запускать:

- `npm run lint`;
- `npm run typecheck`;
- `npm run test:unit -- --ci`.

Подробности:

- [docs/testing/git-checks.md](./git-checks.md)

## Ручные сценарии перед релизом

### Запуск приложения

Проверить:

- приложение стартует;
- экран приветствия/авторизации открывается корректно;
- Sentry/AppMetrica/YaMap initialization не ломает запуск;
- нет crash на холодном старте.

### Авторизация

Проверить:

- вход;
- обработку ошибки входа;
- правильный вход без CAPTCHA, если сервер её не потребовал;
- появление SmartCaptcha только после `captcha_required` при входе;
- обязательную SmartCaptcha перед отправкой кода восстановления;
- SSO: системное окно, web-вход, возврат по deep link и обмен кода на токен;
- восстановление пароля с шестизначным SMS-кодом;
- сохранение/чтение Bearer-токена в Keychain/Keystore.

### Заказы

Проверить:

- после полного закрытия и повторного запуска приложения заказы появляются без
  ручного обновления;
- список заказов открывается;
- обновление списка работает;
- карточка заказа отображает ключевые поля;
- действия доступны только в ожидаемых состояниях;
- модалка подтверждения открывается и закрывается корректно.

### Карта заказов

Проверить:

- карта открывается;
- маркеры отображаются;
- группировка заказов не ломает список;
- открытие заказа с карты работает;
- состояние пустого списка не ломает экран.

### Сеть

Проверить:

- при отключении сети появляется плашка «Нет подключения к интернету»;
- плашка расположена под навигационной шапкой и не перекрывает её кнопки;
- плашка не блокирует нажатия по текущему экрану;
- после восстановления сети плашка автоматически скрывается;
- повторная потеря и восстановление сети корректно обрабатываются без перезапуска;
- после успешной загрузки заказов приложение запускается без сети после полного
  закрытия, сохраняя список, маркеры, настройки и телефоны;
- категории заказов офлайн переключаются мгновенно из кэша без глобального и
  локального спиннера;
- переходы между экранами офлайн не запускают фоновые API-загрузчики;
- предложения, статистика, график и расчёт офлайн не показывают старые онлайн-данные;
  открытый раздел после восстановления сети загружается сам, без перезагрузки,
  со спиннером только когда данных ещё нет;
- создание предложения, сохранение настроек, выход, управление статистикой,
  выбор месяца графика и открытие ошибок графика недоступны офлайн;
- геолокация и пробки на карте скрыты офлайн; блокировка поворота доступна;
- при выходе из аккаунта сохранённые пользовательские данные очищаются.

### Геолокация

Проверить:

- permissions не ломают запуск;
- позиция курьера обновляется;
- повторное нажатие определения позиции снова показывает/обновляет маркер без
  необходимости уходить с карты;
- GPS-зависимые действия ведут себя ожидаемо.
- после полного перезапуска Android названия улиц и районов на карте отображаются по-русски
  онлайн и в сохранённой офлайн-области после полного перезапуска приложения.

### Настройки

Проверить:

- изменение размера шрифта;
- режимы темы «Системная», «Светлая» и «Тёмная»;
- смену системной темы при выбранном режиме «Системная»;
- сохранение выбранной темы после полного перезапуска приложения;
- тёмную карту, шапку, меню, основные экраны и нижние шторки в тёмной теме;
- изменение темы маркеров и масштаба карты независимо от темы интерфейса;
- выбор кафе показывает реальные точки в формате «город, точка», сохраняет выбор,
  выделяет текущую точку и прокручивается при длинном списке;
- сохранение настроек.

Для demo-аккаунта дополнительно проверить фейковое удаление и повторный вход; для
обычного аккаунта кнопки удаления быть не должно.

### Статистика и расчет

Проверить:

- выбор дат;
- нормализацию диапазона;
- обновление данных;
- состояние ошибки API.

### Обратная связь

Проверить:

- список обращений;
- создание обращения;
- выбор изображения/камеры, если зона затрагивалась.

## Что нельзя делать перед релизом без уверенности

Нельзя:

- выполнять опасные реальные действия с заказами только ради проверки;
- оставлять включенный fake/dev режим;
- выпускать релиз с неизвестным красным baseline;
- менять startup или store без повторной проверки основных сценариев.
