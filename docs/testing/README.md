# Документация по тестированию

Этот раздел нужен как единое место, где зафиксированы:

- текущий статус тестов;
- правила unit-тестирования;
- текущий quality baseline;
- релизный чеклист.

Сейчас основной baseline проекта - `lint`, `typecheck` и unit-тесты.

## Структура раздела

### [docs/testing/unit-testing-rules.md](./unit-testing-rules.md)

Правила написания и поддержки unit/component-level тестов.

Нужны для:

- стабильных тестов без реального backend;
- аккуратной работы с fake timers;
- понимания, какие сценарии обязательно покрывать.

### [docs/testing/git-checks.md](./git-checks.md)

Проверка при заливке в Git.

Нужен для:

- GitHub Actions workflow;
- проверки на `pull_request` и `push`;
- настройки branch protection и required status checks.

### [docs/testing/testing-progress.md](./testing-progress.md)

Текущий статус внедрения quality baseline.

Нужен для:

- фиксации текущего состояния baseline;
- контроля ближайших шагов;
- понимания, что уже проверено.

### [docs/testing/release-checklist.md](./release-checklist.md)

Чеклист перед релизом.

Нужен для:

- повторяемой проверки;
- контроля критичных сценариев;
- разделения автоматических и ручных проверок.

## Текущие команды

### Unit-тесты

Базовая команда:

```bash
npm test
```

Стабильная локальная команда:

```bash
npm run test:unit
```

### TypeScript

```bash
npm run typecheck
```

### ESLint

Текущая команда:

```bash
npm run lint
```

Команда использует [eslint.config.js](../../eslint.config.js) под ESLint 10.
Для TS/TSX `rules-of-hooks` проверяется как ошибка, `exhaustive-deps` — как
предупреждение; строгий набор RN-правил не включён. Подробности:

- [docs/quality-baseline.md](../quality-baseline.md)

## Что сейчас считается unit-тестами

Текущие тесты лежат в:

- [__tests__](../../__tests__)

Они покрывают:

- действия с заказом;
- ветки GPS;
- модалки подтверждения;
- аналитику;
- UI-условия карточки заказа;
- fake API guards;
- группировку заказов на карте;
- статистику;
- updater-интервалы.
- Laravel API transport/routes/errors и DTO adapters;
- Bearer-токен в Keychain/Keystore;
- SSO callback/exchange и SmartCaptcha;
- выбор кафе, backend-флаг статистики и фейковое удаление demo-аккаунта;
- стабильность маркера геопозиции Android/Fabric;
- инициализацию geometry iOS/Fabric и фильтрацию некорректных координат MapKit.
- выбор, загрузку и повторную попытку синхронизации офлайн-регионов MapKit.
- создание предложений, сброс черновика и отображение нескольких изображений.
- согласованность JS/нативных версий RN в сохранённом lock-файле;
- iOS version guard и восстановление устаревших Pods на временных заглушках,
  без настоящего `pod install`, сети и установленного iOS SDK.
- запоздавшие ответы настроек, очередь ручного обновления при ошибках и офлайне,
  реальное сохранение и восстановление частичного фильтра заказов;
- метаданные изображений и смешанный выбор фото/видео, обычное сохранение
  оформления меток при разных темах приложения и устройства;
- выбор JDK, Android-команд, аргументов и кодов ошибок на изолированных
  временных инструментах, без реального Gradle, npx или установки приложения.

Свежие результаты и точное число наборов/тестов фиксируются в
[журнале тестирования](./testing-progress.md). В baseline входят сценарии ИИ-рекомендаций, перестроения маршрута,
отмены устаревшего анализа, настроек подсказок карты и регрессий пробок, а также
очистка формы предложения, удаление отдельного вложения, точный multipart с
Unicode/emoji и несколькими изображениями и нормализация всех URL backend.
Detox, нативные сборки и ручной smoke не входят в этот baseline; их результаты
нельзя выводить из зелёного Jest-прогона. Release-проверки ведутся в
[релизном чек-листе](./release-checklist.md).

Отдельные нативные проверки меток исполняют тела методов установленного
`react-native-yamap-plus` без устройства и backend. Они не заменяют UI-smoke; команды и требования
перечислены в [правилах unit-тестирования](./unit-testing-rules.md#нативные-регрессии-маркеров).

Для ручного сравнения модалок в debug-сборке откройте пункт меню «UI заказов (DEV)»: там есть тестовые ошибки графика и отдельная кнопка обычного системного окна Android/iOS. Эти кнопки не отправляют заказы, обжалования и запросы. Окна разрешений ОС (например, геолокации) проверяют отдельно на тестовом устройстве: их UI-предпросмотр не имитирует.

