## Пользовательский сценарий

- Города: Самара и Тольятти. Выбор хранится только на устройстве, не меняет кафе,
  аккаунт или фильтр заказов и не требует сохранения общих настроек.
- По умолчанию выбирается город текущего кафе по названию или координатам.
- Перед скачиванием показывается размер пакета из каталога MapKit.
- Порядок блока одинаков с сайтом: город, размер, статус или прогресс, кнопки.
- Действия: «Скачать», «Пауза», «Продолжить», «Обновить», «Удалить».
  Удаление подтверждается в нижней шторке с единым текстом и кнопками «Нет» и
  «Удалить». На сайте дополнительно возможна кнопка «Докачать» для старого
  неполного пакета тайлов; MapKit такого состояния не использует.
- Показываются прогресс, готовность, дата сохранения и ошибки загрузки.
  Ошибка оформляется одинаково с сайтом: отдельная плашка со значком, мягким
  красным фоном и тематическими цветами в светлом и тёмном режиме.
  Частичная загрузка не помечается «Доступна офлайн».
- Скачать можно один город за раз при активной авторизованной сессии и наличии
  интернета. Переход между экранами не останавливает загрузку.
- Потеря сети или уход приложения в фон ставят загрузку на паузу с возможностью
  автоматического продолжения при возвращении в активное приложение с сетью.
  Ручная пауза требует «Продолжить». Выход из аккаунта отключает автопродолжение.
- Незавершённые задания восстанавливаются после перезапуска. Статус сверяется
  с нативным SDK; очищенная карта не остаётся помеченной как готовая.
- Обновление заказов и вход в настройки не начинают скачивание автоматически:
  новый пакет запускается только кнопкой «Скачать», а остановленный — кнопкой
  «Продолжить».
- Если текущий город не скачан, приложение не показывает случайные тайлы из
  временного кэша MapKit как готовую офлайн-карту. Вместо карты отображаются
  та же подсказка и список сохранённых заказов, что и на сайте; карточка заказа
  открывается прямо из списка.

Состояния скачивания, удаления и отсутствующей карты вручную проверены 7 октября
2026 года на Android и iOS и сопоставлены с мобильным сайтом.

Автоматический прогон 7 октября: `lint`, `typecheck`, 111 наборов / 525
Jest-тестов и три нативные регрессии маркеров прошли; Android Debug и iOS Debug
для Simulator успешно собраны без запуска эмуляторов. Тесты отдельно фиксируют
единый текст удаления, пустое состояние без сохранённых заказов и запрет
одновременного скачивания двух городов.

## Отличия от сайта

Приложение сохраняет нативные городские пакеты Yandex MapKit. Сайт сохраняет
растровые тайлы Tiles API в Cache Storage с прямоугольниками и уровнями 10–14.
Границы, детализация и размер пакетов отличаются. В приложение не переносится
браузерный рендерер, серверный Tiles API или его ключ.

Готовность и необходимость обновления определяет MapKit (`completed`, `outdated`,
`need_update`), вместо браузерного срока хранения 29 дней. Нативный SDK проверяет
доступное место перед скачиванием. Скачивание допускается по мобильной сети.
Непрерывная загрузка в фоне не обещается.

Данные карт хранятся в SDK, метаданные и выбранный город — в AsyncStorage
`jaco_mapkit_city_downloads_v1`. Карты общие для устройства; пользовательский
кеш заказов и токен остаются отдельными и очищаются при выходе из аккаунта.
Офлайн-карта не предоставляет новые заказы и не разрешает менять их статусы.

MapKit может показывать ранее закэшированные просмотренные участки, но приложение
не загружает городской пакет автоматически. Наличие подложки на текущем экране не
означает, что весь город доступен без сети; полную готовность проверяем в разделе
«Офлайн-карты».

Текущий Debug на iOS получает JS из Metro (`AppDelegate.bundleURL`). Полный
холодный запуск без Metro проверяется в Release. При изменении нативного моста
MapKit пересобираются обе платформы; обновления JavaScript недостаточно.

## Проверка на iPhone

Чтобы безопасно показать состояние ошибки в Debug на Android и iPhone, запустите
Metro с принудительным предпросмотром и обновите JavaScript приложения:

```bash
JACO_OFFLINE_MAP_ERROR_PREVIEW=1 JACO_LARAVEL_API=local npm start -- --reset-cache
```

Откройте «Настройки → Офлайн-карты». Выбранный город покажет «Загрузка
прервана», прогресс, тестовую ошибку и действия «Продолжить»/«Удалить».
Нативная пересборка не требуется. Флаг действует только в Debug и не меняет
сохранённую карту; для возврата к обычному состоянию перезапустите Metro без
`JACO_OFFLINE_MAP_ERROR_PREVIEW`.

1. Открыть настройки; проверить размер и готовность ранее скачанной карты.
2. Скачать другой город, поставить на паузу, перейти на другой экран и обратно.
   Загрузка не должна продолжиться без нажатия «Продолжить».
3. Продолжить, отключить сеть, затем включить: загрузка должна возобновиться.
4. Закрыть приложение во время загрузки и открыть снова с сетью: прогресс
   восстанавливается из SDK, завершённая карта показывает «Доступна офлайн».
5. Полностью закрыть приложение, включить авиарежим и открыть карту:
   сохранённые заказы и подложка текущего скачанного города должны отображаться.
6. Удалить пакет с подтверждением. Другой город должен остаться сохранённым;
   обновление заказов не должно скачать удалённый пакет заново.
7. Проверить светлую/тёмную тему, крупный шрифт, малую ширину и нижний Safe Area.

Источник нативного контракта:
[Yandex MapKit: офлайн-карты](https://yandex.ru/maps-api/docs/mapkit/ios/generated/tutorials/map_offline.html).

## Исправления доступности — 19 ноября 2026

Внесено в код, проверяет разработчик. Сборки, тесты и ручные проверки агентом
не запускались. Ранее приведённые результаты относятся к предыдущим версиям.

- `completed` и `outdated` дают пригодную офлайн-карту; для `outdated` отдельно
  показывается «Есть обновление». `need_update` не приравнивается к `outdated`:
  пакет считается непригодным до восстановления.
- Пригодность (`availability`) отделена от состояния задания (`status`). Во
  время обновления/паузы прежняя карта остаётся доступной, если SDK возвращает
  тот же установленный релиз, который ранее подтверждён пригодным.
- Нативный мост Android/iOS возвращает идентификатор установленного релиза и
  локальный каталог регионов. Чтение локального каталога не требует запроса
  списка регионов в сеть. Завершённый пакет не блокируется старой ошибкой загрузки.
- При восстановлении все записи сначала проверяются SDK. Старый `outdated`
  нельзя объявлять пригодным по одному сохранённому статусу: ранее в него
  объединялся также `need_update`. Словарь `status` и версия хранилища 1 сохранены;
  новые поля необязательны для чтения старым JS.
- Дата сохранения не сбрасывается при начале обновления. Временная ошибка чтения
  SDK не стирает намерение автопродолжения. Ручная пауза остаётся ручной.

Изменения нативной библиотеки сохранены в
`patches/react-native-yamap-plus+6.12.0.patch`, а не только в `node_modules`.
Новых npm-зависимостей нет. Нужны пересборки Android/iOS и обновление iOS codegen
через установку pods. Для холодного запуска требуется Release.

Общие сценарии, команды и ожидаемые результаты:
[ручная проверка сайта, Android и iPhone](./offline-map-manual-check.md).


## Обновление приложения: исправление преждевременного завершения — 19 ноября 2026

Кнопка «Обновить» возвращена для скачанной пригодной карты на Android и iOS.
Нажатие явно вызывает startDownload и для completed. Служебные сообщения
о «карте без изменений» не показываются. Не добавлены задержки, таймеры успеха,
удаление старого пакета или принудительная очистка данных.

Подтверждённый дефект кода: startOfflineRegionDownload разрешал Promise сразу
после команды startDownload. JS затем считывал completed/progress=1 старого
пакета и принимал это за завершение попытки, освобождал слот и снимал намерение
автопродолжения. Установленный релиз не сравнивался с релизом каталога, а события
RegionListener не учитывались. По одному мельканию интерфейса нельзя различить
это преждевременное завершение, отсутствие нового релиза и ошибку SDK.

Теперь мост передаёт availableReleaseTime из Region.releaseTime и факт перехода
в downloading после текущей явной команды. RegionListener сохраняет этот факт,
даже если JS не успел опросить короткую загрузку. Общая ошибка OfflineCacheManager
передаётся активной загрузке так же, как ошибка региона, вместо сохранения только
в диагностике каталога. Новая попытка сбрасывает сведения предыдущей попытки.
Нативные изменения сохранены также в patch-package.

Старый completed больше не завершает ожидающую попытку при новом или неизвестном
релизе каталога. Ожидание заканчивается фактическим переходом SDK, установкой
другого релиза, ошибкой либо completed с совпадающим/более новым установленным
релизом относительно каталога. Последний случай означает, что пакет уже
соответствует данным каталога SDK; это не доказательство свежего сетевого запроса
или повторного скачивания. Дата сохранения не меняется для прежнего релиза.
Прежний искусственный предел ожидания 60 секунд удалён. Пользователь может
отменить подготовку. Старая пригодная карта и её галочка остаются доступными.

Источники контрактов: OfflineCacheManager.startDownload, getDownloadedReleaseTime,
Region.releaseTime и RegionListener в установленных SDK Android 4.42.0-full/iOS;
официальная документация:
https://yandex.com/maps-api/docs/mapkit/com/yandex/mapkit/offline_cache/OfflineCacheManager.html
https://yandex.ru/maps-api/docs/mapkit/com/yandex/mapkit/offline_cache/Region.html

Добавлены/обновлены регрессии: наличие и действие кнопки у completed, старый
completed при новом/неизвестном релизе каталога, совпадающие релизы без изменения
даты, загрузка между двумя JS-опросами, поздняя ошибка и продолжение после паузы.
Тесты и сборки агентом не запускались. Причина конкретного ответа внешнего SDK
на устройстве ещё не подтверждена. Нельзя утверждать, что на нём не было новой
версии, только по прежнему скриншоту.

Ручная проверка после пересборки Release, отдельно Android затем iOS:

1. У ранее скачанного Тольятти есть «Обновить» и галочка.
2. Нажать «Обновить» без ручной паузы. При реальном downloading появляются
   проценты/пауза; при совпадающих релизах старый пакет остаётся готовым, дата
   не обновляется и служебных сообщений нет. Ошибка сохраняется до повтора.
3. Если началось downloading, проверить ручную паузу, старую карту офлайн,
   восстановление после закрытия и продолжение. Отдельно проверить потерю сети.
4. Повторить основные офлайн-сценарии, уже пройденные на прошлой сборке.

перемещение/масштабирование без сети, Force stop и холодный офлайн-запуск,
восстановление карты/меток/карточки заказа и галочки в Android-эмуляторе.
